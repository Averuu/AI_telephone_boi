# Taskmaster: анализ рисков для Odoo 20.0

## О проекте

Taskmaster добавляет в Odoo Project анализ рисков проекта или отдельной задачи. Модуль
формирует отчёт по правилам и при настройке внешнего ИИ-сервиса дополняет его текстовым анализом.
Без API-ключа модуль продолжает работать: ИИ не является обязательным условием использования.

## Возможности

- Анализ всех доступных пользователю задач проекта в пределах настроенного лимита или одной задачи.
- Поиск просроченных и близких дедлайнов, отсутствующих исполнителей и сроков, давно не обновлявшихся задач.
- Учёт незакрытых зависимостей и превышения запланированных часов при наличии соответствующих полей.
- Сводка `Open / Overdue / Unassigned`, список сигналов риска и необязательный ИИ-анализ.
- Подключение OpenAI-совместимого сервиса с форматом chat completions.

## Как пользоваться

| Что анализировать | Где находится кнопка Risk analysis |
|---|---|
| Весь проект | Панель управления kanban-доски задач проекта, над задачами |
| Одну задачу | Шапка формы задачи |

1. Откройте проект или задачу и нажмите **Risk analysis**.
2. В открывшемся диалоге проверьте выбранный проект или задачу. Если проект не определился
   автоматически, выберите его вручную.
3. Запустите анализ и дождитесь результата. Во время запроса старый результат скрывается,
   а подсказка `Analysis may take up to a minute.` предупреждает о возможном ожидании.
4. Прочитайте сводку `Open / Overdue / Unassigned`, затем ИИ-анализ или причину его отсутствия,
   затем список `Rule-based signals`.

Обе кнопки используют один диалог. Если API-ключ не настроен или сервис недоступен,
отчёт по правилам всё равно отображается вместе с краткой причиной отсутствия ИИ-анализа.

## Требования и установка

Модуль предназначен для **Odoo 20.0**. Зависимости из манифеста: модуль Odoo `project`
и Python-библиотека `requests`.

Разместите каталог модуля под именем `taskmaster` в одной из директорий `addons_path`
из конфигурации Odoo. Команды ниже запускаются из корня исходников Odoo:
`odoo.conf` и `odoo_test1` приведены как пример конфига и тестовой базы проекта;
замените их на свои значения.

Первая установка:

```bash
python odoo-bin -c odoo.conf -d odoo_test1 -i taskmaster
```

Обычный запуск:

```bash
python odoo-bin -c odoo.conf -d odoo_test1
```

Обновление установленного модуля:

```bash
python odoo-bin -c odoo.conf -d odoo_test1 -u taskmaster
```

Подробности обновления и отладки описаны в [руководстве для разработчика](docs/development.md#цикл-обновления).

## Настройка ИИ

Без настройки агент выдаёт только отчёт по правилам. Параметры живут в `ir.config_parameter`
(Settings → Technical → System Parameters, нужен режим разработчика) или через shell:

```python
icp = env['ir.config_parameter'].sudo()
icp.set_str('taskmaster.api_key', '<ключ>')        # в 20.0 set_param/get_param удалены
icp.set_str('taskmaster.api_url', 'https://api.openai.com/v1/chat/completions')  # необязательно
icp.set_str('taskmaster.model', 'gpt-4o-mini')                                    # необязательно
env.cr.commit()
```

- Совместим любой сервис с форматом chat completions (`choices[0].message.content`).

Особенности используемого API параметров и статус источников описаны в
[руководстве по разработке](docs/development.md#особенности-odoo-200).

## Данные и безопасность

- Данные задач читаются с правами текущего пользователя, без `sudo()` для бизнес-данных.
  Анализ не должен раскрывать задачи, к которым у пользователя нет доступа.
- При включённом ИИ названия и описания задач уходят во внешний API. Перед использованием
  реальных данных необходимо принять решение по приватности: маскирование или локальная модель.
  Это направления развития, а не обещание уже реализованной защиты.
- Ключи и данные клиентов нельзя коммитить; ключи нельзя писать в логи.
  Содержимое задач не должно логироваться на уровне INFO.
- Текст задач недоверенный и может содержать инъекции. Системный промпт рассматривает его как данные,
  а не инструкции; результат сохраняется в санитизируемом поле `fields.Html`.
- Отчёт по правилам формируется всегда, ИИ остаётся необязательной надстройкой.

## Ограничения

- Запрос к ИИ блокирующий (`LLM_TIMEOUT` = 60 с) и занимает рабочий процесс Odoo.
  Для продакшена нужна очередь; она пока относится к [плану развития](docs/roadmap.md).
- Объём анализа и объём отправляемых в ИИ данных ограничены константами модуля.
- Сигналы зависят от доступных полей задач. Если необязательного поля нет, соответствующий
  сигнал может молча пропускаться. Имена ряда полей ещё требуют проверки.
- Оценка основана на доступных данных и правилах, а не гарантирует выявление всех рисков.

Подробный [статус проверок и непроверенные поля](docs/testing.md) хранится отдельно.
Автоматические тесты пока не реализованы; пример в документации является незапущенным наброском.
