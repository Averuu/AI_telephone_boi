# AGENTS.md: правила работы с Taskmaster

Прочитай этот файл целиком до первого изменения кода. Модуль для **Odoo 20.0** добавляет
анализ рисков проекта и отдельной задачи через один wizard. Пользовательская документация:
[README.md](README.md). Подробности кода и разработки находятся в `docs/`.

## Обязательные ограничения

1. Данные задач читай с правами текущего пользователя. Не добавляй `sudo()` для бизнес-данных,
   в том числе в `_collect_*`. `sudo()` допустим только для чтения `ir.config_parameter` (ключ API).
2. Отчёт по правилам формируется всегда; ИИ является необязательной надстройкой. Без ключа
   или при сбое сервиса сохраняй результат и краткую причину отсутствия ИИ-анализа.
3. Текст задач недоверенный: он может содержать инъекции. Сохраняй требования системного промпта
   и санитизацию результата в `fields.Html`.
4. Не коммить ключи и данные клиентов, не пиши ключи в логи. Не логируй содержимое задач на уровне INFO.
   Названия и описания задач уходят во внешний API: учитывай приватность при изменениях интеграции.
5. Не используй `ir.model.access.csv`, `attrs`, `<tree>`. Особенности `ir.access`, типизированных
   методов `ir.config_parameter` и другие ловушки собраны в
   [руководстве по разработке](docs/development.md#особенности-odoo-200).
6. Перед использованием API из памяти (ORM, права, view, поля `project.*`) сверяйся с
   [документацией Odoo 20.0](https://www.odoo.com/documentation/20.0/developer/), не с версиями 17–19.
   Если документация недоступна или API остаётся неясным, не угадывай: попроси у пользователя выдержку в txt.
7. Любое новое поле `project.task`/`project.project` проверяй через `_fields` или документацию 20.0,
   как сделано в агенте. При отсутствии поля сигнал может молча пропускаться.
8. Не переименовывай модели и xml id без необходимости. При переименовании предупреди
   о старых записях и необходимости проверки на чистой БД.
9. Новую модель добавляй вместе с правами в `security/ir.access.csv` и файлом в `data` манифеста
   в правильном порядке. Для TransientModel тоже нужны права.
10. Работай маленькими шагами. После изменения укажи, нужен ли перезапуск или `-u taskmaster`.
    Не помечай изменение поведения выполненным без запуска на тестовой БД или соответствующего теста;
    если проверка недоступна, явно укажи это.

## Проверка изменений

Команды запускаются из корня исходников Odoo. `odoo.conf` и `odoo_test1` обозначают конфиг
и тестовую базу проекта. Полный цикл: [development.md](docs/development.md#цикл-обновления).

- Только Python: перезапуск сервера; XML, CSV, manifest или новые поля: `-u taskmaster`.
- Проверка загрузки: `python odoo-bin -c odoo.conf -d odoo_test1 -u taskmaster --stop-after-init`.
- Тесты: `python odoo-bin -c odoo.conf -d odoo_test_tests -i taskmaster --test-enable --test-tags /taskmaster --stop-after-init`.

Зафиксированное состояние, непроверенные поля, отсутствие готовых тестов, набросок и приоритеты:
[testing.md](docs/testing.md). Не представляй набросок теста как реализованную проверку.
При правках только документации проверяй ссылки и сохранность содержания; запуск Odoo не требуется.
